二、错误分析（专用版 3 条错例）

① 「你怎么才回我」：期望 情绪不满 → 实判 催问回复（conf 0.59）

类型：类间语义重叠。「催问回复」=「催我回话或问我怎么还没回」，「情绪不满」=「生气、抱怨、暗示我做得不好」—— 这句话同时满足两者，属定义边界内的固有模糊。旁证：几乎同义的「你怎么还不回我」判对（催问回复 0.84），一对一对错说明是边界摇摆。

建议：instructions 加裁决规则（如「带责问语气的催→情绪不满；就事论事的催→催问回复」），或调整该条标注。

② 「晚上吃什么」：期望 提问求助 → 实判 其他（conf 0.19）

类型：低置信漂移到「其他」。专用版「提问求助」例句里就有「中午吃什么」，理论上是送分题（通用版判对）； 但专用版 instructions 要求「先判断她是不是在要我的关注或回应，再归具体类别」——日常短问句在第一步落空后没有明确出口， 模型犹豫后漂进「其他」，违反了「能归入某类时不要选其他」。

建议：专用 instructions 为日常问句补显式出口（「吃什么 / 去哪 这类问句 → 提问求助」）； 若语义是「约着一起吃」应归「约时间安排」，可顺手写清边界。

③ 「看了个超好笑的视频」：期望 分享内容 → 实判 闲聊分享（conf 0.55）

类型：gold 标注与定义文本不一致。专用版「分享内容」=「转发文章、视频、音乐、链接给我」， 而这句是转述自己的见闻，恰好落在「闲聊分享」的例句模式（『刚看到一只猫』）上——模型的选择反而更贴合定义文本，更像标注侧问题。

建议：把「分享内容」描述改为「提到具体作品并分享，无论转发还是转述」，或修订 gold。

七、模型输出的算分规则（后处理判定）

7.1 原始输出三题结构

题type直接输出后处理（watcher.py:353 shape_result）
intentchoicechoice=选项标签 + probabilities（13 类分布） 取 choice → value；评测命中 = value == 金牌（严格字符串）
urgencyscorescore=期望分 = Σ(档位值×probabilities[档]) + legend round(score) 查 legend → 取「：」前段为 label（如 0.87→1→「有空回一下」）
need_replynoulnoul=P(对方在等我回复) 直接当概率用：>0.5 判「是」（阈值硬编码于 notify 的 nr > 0.5）

注：期望档与 argmax 档可能不一致（如 P=(0.45,0.30,0.25) 时 argmax=0 但期望 0.80 → 定档 1）；watcher 采用期望档。 confidence 为模型自报把握度，不参与命中判定，可作线上降级阈值（<0.4 不可信）。
